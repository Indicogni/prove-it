Checkpoint 3: Fixed-Width Ring Buffer

Prove bounds safety and FIFO queue refinement for a bounded circular buffer.

Checkpoint Spec · Bounded Circular Queue vs. Abstract `List α` 
-- SpecQueue: plain `List α` (`enqueue` appends at back, `dequeue` pops front, max `cap`).
-- RingBuf: fixed capacity `cap > 0`, modular index arithmetic `(head + len) % cap`.
-- Prove: (1) zero out-of-bounds indices, (2) `toList (push rb x) = toList rb ++ [x]` when `len < cap`.
Socratic Gate · Commit to a Prediction Unanswered · Locks on commit

In a circular ring buffer of capacity `cap > 0`, why should the state store `(head : Fin cap)` and `(len : Nat)` (`len ≤ cap`) instead of just `(head : Fin cap)` and `(tail : Fin cap)`?

Why this happens:

Bringing `Fin`, Modular Arithmetic, and Refinement Together

Kernel network rings (io_uring, DPDK) and telemetry queues use fixed-capacity circular buffers to guarantee zero heap allocation on hot paths. Proving that modular wrap-around (head + i) % cap refines an ordinary List α FIFO queue seals off both out-of-bounds panics and silent wrap-overwrite corruption.
