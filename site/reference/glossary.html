Earned-Jargon Glossary

Every formal term in Prove It is earned by solving a concrete engineering problem first. Filter by course part or search any Lean, TLA+, or verification concept below.

Part I Earned in unit →

Total Function

Plain-English Meaning: A function guaranteed to return a valid output for every possible input of its parameter types—never throwing exceptions, looping forever, or dereferencing null.

Lean 4 Mechanism: Default for all `def` functions in Lean 4 (Ch 01).

Part I Earned in unit →

Saturating Subtraction

Plain-English Meaning: Defining `a - b = 0` on `Nat` whenever `a < b` so natural numbers stay closed without throwing runtime exceptions.

Lean 4 Mechanism: `(10 : Nat) - 12 = 0` (Ch 01).

Part I Earned in unit →

Product Type (`structure`)

Plain-English Meaning: A record packing Field A AND Field B together; total state count multiplies (`|A| × |B|`).

Lean 4 Mechanism: `structure Config where ...` (Ch 02).

Part I Earned in unit →

Sum Type (`inductive`)

Plain-English Meaning: A tagged choice representing Variant A OR Variant B (mutually exclusive); state count adds (`|A| + |B|`), making illegal combinations unrepresentable.

Lean 4 Mechanism: `inductive Session | anonymous | active (uid : Nat)` (Ch 02).

Part I Earned in unit →

Boolean Reflection (`Decidable`)

Plain-English Meaning: Connecting an executable `Bool` check (0/1 data) to a rich mathematical specification `Prop` via `eval x = true ↔ Spec x`.

Lean 4 Mechanism: `Decidable P`, `decide`, `↔` (Ch 03).

Part I Earned in unit →

Gear 1 (Bounded BFS Model Checking)

Plain-English Meaning: Exhaustively exploring all reachable action interleavings up to depth `k` to catch shallow protocol bugs and emit minimal counterexample traces.

Lean 4 Mechanism: 35-line pure `bfs` in Lean + `#guard` (Ch 04).

Part II Earned in unit →

Lean Infoview

Plain-English Meaning: The live proof-state inspector showing **Objects** (variables), **Hypotheses** (assumptions in scope), and **⊢ Goal** (remaining obligation).

Lean 4 Mechanism: Interactive split-view in every chapter (Ch 05).

Part II Earned in unit →

Curry-Howard Correspondence

Plain-English Meaning: The exact identity between logical propositions and types: proving `P → Q` is writing a total function taking a proof of `P` to a proof of `Q`.

Lean 4 Mechanism: `theorem` bodies typechecked by Lean's kernel (Ch 05).

Part II Earned in unit →

Garden-of-Eden State

Plain-English Meaning: An unreachable syntactic state `s` where `Safe s` happens to hold right now, yet one transition `Next s s'` crashes into an unsafe state `¬Safe s'`—breaking naive induction.

Lean 4 Mechanism: Eliminated by Inductive Strengthening (Ch 08 & Lab 2).

Part II Earned in unit →

Gear 2 (Inductive Strengthening)

Plain-English Meaning: Adding structural invariants (`Inv s := Safe s ∧ Helper s`) so `Init s → Inv s` and `Inv s → Next s s' → Inv s'` hold across infinite depths and unbounded integers.

Lean 4 Mechanism: `Reachable s → Safe s` (Ch 08).

Part III Earned in unit →

Subtype & Runtime Proof Erasure

Plain-English Meaning: Bundling a runtime value `x : α` with a compile-time proof `h : P x` (`{ x : α // P x }`). Lean erases `h` to zero bytes (`lcErased`) in machine code.

Lean 4 Mechanism: `Subtype`, `Fin cap`, `if h : ...` (Ch 09 & Lab 4).

Part III Earned in unit →

Bit-Blasting & LRAT (`bv_decide`)

Plain-English Meaning: Translating fixed-width 64-bit hardware arithmetic (`BitVec 64`) into SAT and checking an unsatisfiability certificate to catch `2^64` wrap-around bugs.

Lean 4 Mechanism: `import Std.Tactic.BVDecide`, `bv_decide` (Ch 10 & Lab 5).

Part III Earned in unit →

Well-Founded Termination

Plain-English Meaning: Proving a measure (`buf.size - offset`) strictly decreases on every recursive call—turning termination proofs into compile-time Denial-of-Service protection.

Lean 4 Mechanism: `termination_by`, `decreasing_by`, `fun_induction` (Ch 11).

Part III Earned in unit →

Refinement Mapping & Stuttering

Plain-English Meaning: An abstraction function `abs : Impl → Spec` proving optimized code implements a tiny spec; internal housekeeping steps (compaction, GC) satisfy `abs s' = abs s`.

Lean 4 Mechanism: `abs (compact s) = abs s` (Ch 12).

Part IV Earned in unit →

Trusted Computing Base (TCB)

Plain-English Meaning: The minimal set of components (`Spec.lean` + Lean kernel + audit gate) that must be honest for your verification guarantee to hold—excluding untrusted AI agents!

Lean 4 Mechanism: `#print axioms` & `lake exe verigate` (Ch 13 & Lab 3).

Part IV Earned in unit →

Non-Vacuity Witness

Plain-English Meaning: A companion theorem `∃ x, Pre x` proving your safety theorem's preconditions are satisfiable by real inputs—blocking vacuous `False → Anything` cheats.

Lean 4 Mechanism: Enforced in `Spec.lean` & `verigate` (Ch 13–14).

Part IV Earned in unit →

Stream-Safe Framing

Plain-English Meaning: Proving `decode (encode pkt ++ rest) = some (pkt, rest)` for all trailing bytes `rest`, ruling out TCP concatenation and frame-smuggling vulnerabilities.

Lean 4 Mechanism: TLV packet framing (Ch 15).

Part IV Earned in unit →

Differential Reference Oracle

Plain-English Meaning: Executing a mathematically verified Lean model (`lake exe oracle`) alongside a production Rust/Go/TS/Python service on thousands of adversarial traces.

Lean 4 Mechanism: `lake exe oracle` + `fuzz_against_oracle.py` (Ch 16).
